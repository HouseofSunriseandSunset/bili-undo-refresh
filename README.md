# 哔哩哔哩 PC 客户端「撤回刷新」插件

> 给哔哩哔哩 PC 客户端的首页「推荐」加一个能力：**刷新之后可以撤回**。
> 刷出一批新视频后手滑点错了？一键回到上一批。撤回后还能**重做**。

- 只作用于首页「推荐」，不影响播放器、动态、直播等其他页面
- **不需要安装 Node.js** —— 安装脚本会借用客户端自带的运行时
- 会修改客户端 `app.asar`，但**自动备份原版**，`uninstall.cmd` 一键还原
- 撤回时**不发起额外网络请求**，不伪造、不上传任何数据

支持版本：哔哩哔哩 PC 客户端 **1.17.5**（完整验证过）

---

## 功能

| 功能 | 说明 |
| --- | --- |
| 撤回刷新 | 回到上一次刷新前的推荐列表（快捷键 `Alt+Z`） |
| 重做 | 回到撤回前的那一批（快捷键 `Alt+Shift+Z`） |
| 多级撤回 | 默认保留最近 6 批，可连续回退 |
| 保留下拉内容 | 撤回时会把「下拉加载出来的视频」一起还回来，不会只剩第一屏 |
| 严格区分刷新类型 | 下拉加载更多只往后追加视频，**不计入**撤回历史 |
| 悬浮面板 | 与客户端观感一致的白色小面板，**长按可拖动**，位置自动记住（右键撤回图标可清空历史） |

> 面板：`↺` 撤回刷新（右上角数字 = 还能撤回几步）、`↻` 重做。
> 两者都不可用时面板会自动隐藏，不干扰界面。

## 安装

### 方式一：下载打包好的（推荐，给普通用户）

1. 到 Releases 页面下载 `bili-undo-refresh-<版本>.zip`
2. 解压，**完全退出哔哩哔哩客户端**（含托盘图标）
3. 双击 `install.cmd`，按提示操作
4. 启动客户端 → 首页「推荐」→ 点一次客户端自带的刷新按钮 → 右下角出现面板即成功

`install.cmd` 会自动查找客户端目录（注册表 → 常见目录）。
如果没找到，把安装目录作为参数传进去：

```bat
install.cmd "D:\bilibili"
```

### 方式二：用本仓库源码

把本仓库下载下来，直接双击 `install.cmd` 即可（脚本和方式一完全相同）。

### 卸载

```bat
uninstall.cmd
```

会从原版备份还原客户端文件，并删除插件配置。备份文件保留在客户端目录，可手动删除 `app.asar.bak-*`。

## 它是怎么工作的

首页「推荐」每次请求都是同一个接口，但**参数决定了两种完全不同的语义**（实测 1.17.5）：

| 操作 | 请求参数 | 语义 | 是否产生可撤回点 |
| --- | --- | --- | --- |
| 首次进入推荐 | `fresh_idx=1&fresh_type=0&ps=30` | **替换**列表 | 作为基准批次 |
| 点客户端刷新按钮 | `fresh_idx=1&fresh_type=3&ps=30` | **替换**列表 | 是 |
| 下拉加载更多 | `fresh_idx=2/3/4…&fresh_type=4&ps=12` | **追加**（只往后加视频） | 否 |

```
GET https://api.bilibili.com/x/web-interface/wbi/index/top/feed/rcmd?fresh_idx=1&ps=30&...
返回 { code:0, data:{ item:[ ... 30 条 ... ] } }
```

插件在**页面主世界**劫持 `window.fetch`：

- 拿到「替换」类响应 → 把响应文本推进批次栈
- 拿到「追加」类响应（下拉加载更多）→ 挂到当前批次上，**不产生可撤回点**
- 点撤回 → 让下一次请求**直接返回上一批的响应文本**（含它之后的全部追加批次合并结果），
  **不发起真实网络请求**；页面用自己的渲染逻辑把旧内容画回来

因为是把「上一批的真实响应」重新交给页面，所以是**数据级撤回**，不需要猜 DOM 结构。

> 实现中有两个容易踩的坑（都已处理）：撤回触发的那次刷新可能连发多个请求（回声），
> 以及撤回/重做必须显式区分意图。详见代码注释。

## 可调参数

| 文件 | 参数 | 说明 |
| --- | --- | --- |
| `main-world.js` | `MAX = 6` | 最多保留多少批 |
| `main-world.js` | `FEED_RE` | 推荐接口正则，客户端换接口时改这里 |
| `main-world.js` | `parseFeedParams()` | 判定「替换 / 追加」的规则（`fresh_idx <= 1` 为替换） |
| `main-world.js` | `SUPPRESS_MS` | 撤回后抑制回声请求的时间窗口 |
| `preload.js` | `REFRESH_SELECTORS` | 客户端自带刷新按钮的选择器 |
| `preload.js` | `PINK` | 主题色（默认 B 站粉 `#FB7299`） |

改完这些文件**不需要重新安装补丁**，重启客户端即可生效。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 右下角没有面板 | 确认客户端已重启；移动过插件目录就重新跑一次 `install.cmd` |
| 点撤回提示「没有可撤回的内容」 | 还没刷新过（下拉加载更多不算刷新） |
| 刷新后数字不动 | 客户端版本更新后接口参数可能变了 → 看 `%USERPROFILE%\bili-undo-refresh.log`，调整 `FEED_RE` |
| 撤回后页面没变化 | 看日志有没有「撤回 → 回放」；没有的话多半是刷新按钮选择器要更新 |
| 安装报 `EPERM` | 客户端还在运行，完全退出后重试 |
| 客户端更新后失效 | 更新会覆盖 `app.asar`，重跑一次 `install.cmd` |
| 杀毒软件报警 | 脚本会改 `app.asar` 并注入一行 `require`，源码全部可读，可自行审阅 |

## 目录说明

| 文件 | 作用 |
| --- | --- |
| `install.cmd` / `install.js` | 安装（Windows 一键 / 命令行） |
| `uninstall.cmd` / `uninstall.js` | 卸载（从备份还原） |
| `loader.js` | 主进程加载器（注入到 asar 的那一行 `require` 指向它） |
| `preload.js` | 渲染进程脚本：注入钩子 + 绘制面板 + 快捷键 |
| `main-world.js` | 页面主世界钩子：识别刷新类型 + 缓存批次 + 撤回回放 |
| `asar-lib.js` | 纯 Node 实现的 asar 读写库（无第三方依赖） |
| `client-locator.js` | 自动定位客户端安装目录 |
| `config.template.json` | 配置模板（安装时生成 `config.json`） |
| `开始使用.txt` | 打包 zip 时附带的简短说明 |
| `tools/make-package.js` | 重新生成发布用 zip |

## 重新打包

改了代码要发布新版本：

```bash
# 1) 改 package.json 里的 version
# 2) 生成 dist/bili-undo-refresh-<版本>.zip
node tools/make-package.js
```

然后把这个 zip 上传到 GitHub 的 Release。
